```rust
/// Calibrate multiple volatility slices sequentially with calendar spread penalty.
///
/// Slices are sorted by expiry T (shortest to longest) and calibrated in order.
/// Each slice after the first includes a penalty for theta < prev_theta to enforce
/// monotonically non-decreasing ATM total variance across expiries.
///
/// Results are returned in T-sorted order (ascending).
pub fn calibrate_surface(
    slices: &[SliceInput],
    config: &DirectCalibConfig,
) -> Vec<DirectCalibResult> {
    if slices.is_empty() {
        return Vec::new();
    }

    // Sort slice indices by T ascending
    let mut indices: Vec<usize> = (0..slices.len()).collect();
    indices.sort_by(|&a, &b| {
        slices[a]
            .t
            .partial_cmp(&slices[b].t)
            .unwrap_or(std::cmp::Ordering::Equal)
    });

    let mut results = Vec::with_capacity(slices.len());
    let mut prev_theta: Option<f64> = None;

    for &idx in &indices {
        let slice = &slices[idx];
        let result = calibrate_slice_with_prev(slice.k, slice.w, config, prev_theta);
        prev_theta = Some(result.theta);
        results.push(result);
    }

    results
}
```

Key design notes:
- The function sorts by T ascending, then iterates, passing `prev_theta` to each subsequent slice via `calibrate_slice_with_prev` which already exists from Phase 15.
- The first slice gets `prev_theta = None`, so no calendar penalty applies -- identical to `calibrate_slice`.
- Results are returned in T-sorted order (ascending), consistent with the sequential nature.
- The calendar penalty is SOFT (quadratic), not a hard barrier. The `lambda_calendar` weight in `DirectCalibConfig` controls the monotonicity enforcement strength.
- No changes needed to `DirectCalibConfig` -- `lambda_calendar` field already exists with default 10.0.
- No changes to `calibrate_slice` or `calibrate_slice_with_prev` -- they are used as-is.
- The `SliceInput` struct already exists from Phase 15.
