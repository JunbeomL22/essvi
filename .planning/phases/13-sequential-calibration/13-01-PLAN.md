**1. Extend CrudeCalibConfig** with a new field:

```rust
/// Penalty weight for calendar spread (theta monotonicity) violations.
/// Used by calibrate_surface to penalize theta < prev_theta.
pub lambda_calendar: f64,
```

Add to the Default impl with value `10.0` (strong enough to enforce monotonicity in practice, but not so extreme as to distort fits).

**2. Create a SliceInput struct** for passing multi-slice data:

```rust
/// Input data for one volatility slice in a multi-slice calibration.
#[derive(Debug, Clone)]
pub struct SliceInput<'a> {
    /// Time to expiry.
    pub t: f64,
    /// Log-moneyness values for this slice.
    pub k: &'a [f64],
    /// Market total variance values for this slice.
    pub w: &'a [f64],
}
```

**3. Implement a private helper `calibrate_slice_with_prev`** that is identical to `calibrate_slice` but accepts an optional `prev_theta: Option<f64>` parameter. When `prev_theta` is `Some(prev)`, the objective function adds:

```
lambda_calendar * max(0, prev - theta)^2
```

This penalizes any theta below the previous slice's fitted theta. The penalty is quadratic to provide a smooth gradient for the optimizer.

Implementation approach:
- Extract the core objective logic from `calibrate_slice` into this new function
- `calibrate_slice` becomes a thin wrapper that calls `calibrate_slice_with_prev(k_slice, w_market, config, None)`
- `calibrate_slice_with_prev` signature:
  ```rust
  fn calibrate_slice_with_prev(
      k_slice: &[f64],
      w_market: &[f64],
      config: &CrudeCalibConfig,
      prev_theta: Option<f64>,
  ) -> CrudeCalibResult
  ```
- Inside the objective closure, after computing SSE + lambda * butterfly_penalty, add:
  ```rust
  if let Some(prev) = prev_theta {
      let shortfall = (prev - theta).max(0.0);
      total += config.lambda_calendar * shortfall * shortfall;
  }
  ```
- When prev_theta is provided, use it as the lower bound hint for theta_init to bias the multi-start search toward valid regions:
  ```rust
  let theta_init = if let Some(prev) = prev_theta {
      prev.max(median_w).clamp(lb[0], ub[0])
  } else {
      median_w.clamp(lb[0], ub[0])
  };
  ```

**4. Implement `calibrate_surface`:**

```rust
/// Calibrate multiple volatility slices sequentially with calendar spread penalty.
///
/// Slices are sorted by expiry T (shortest to longest) and calibrated in order.
/// Each slice after the first includes a penalty for theta < prev_theta to enforce
/// monotonically non-decreasing ATM total variance across expiries.
pub fn calibrate_surface(
    slices: &[SliceInput],
    config: &CrudeCalibConfig,
) -> Vec<CrudeCalibResult>
```

Implementation:
- Create a mutable copy of slices sorted by T (ascending). Use indices to track the sort order.
- Initialize `prev_theta = None`.
- For each slice in sorted order:
  - Call `calibrate_slice_with_prev(slice.k, slice.w, config, prev_theta)`
  - Store result
  - Set `prev_theta = Some(result.theta)`
- Return results in the SORTED order (by T ascending), NOT the original input order. This is consistent with the sequential nature of the calibration -- the caller should expect results ordered by expiry.

Key design notes:
- The calendar penalty is SOFT (quadratic penalty), not a hard barrier. This means theta may still decrease slightly if the data strongly demands it, but the penalty pushes toward monotonicity. The lambda_calendar weight controls the tradeoff.
- The refactoring of calibrate_slice to use calibrate_slice_with_prev internally ensures no behavioral change for single-slice users -- calibrate_slice passes prev_theta=None, so the calendar penalty term is always zero.
- Do NOT modify the existing calibrate_slice public API signature. It remains backward-compatible.
